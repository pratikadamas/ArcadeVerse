01 / Getting Started

Platform Overview

ArcadeVerse is an open-source community arcade station engineered for Nexus Spring of Code (NSOC) – Winter Edition 2026. It unifies dozens of independently built mini-games into a single modern, distraction-free player experience.

The platform is constructed on modern web standards (HTML5, CSS3, Vanilla ES6+ JavaScript) with zero runtime bundler friction. Developers build their games in complete directory isolation, submit pull requests without git conflicts, and receive instant algorithmic credit on the live Hall of Fame leaderboard.

Directory Isolation

Every game lives inside games/<game-name>_<your-handle>/, eliminating code collisions.

Zero Frameworks

Pure HTML5, CSS3, and JavaScript. Lightning-fast 60 FPS Canvas execution without dependency bloat.

Live Gamification

Algorithmic in-app scoring, dual-track prestige badges, and high-resolution trophy certificates.

01 / Getting Started

Design Philosophy

ArcadeVerse follows four foundational tenets designed to make open source participation pleasant, educational, and sustainable:

  • Zero Merge Conflict Architecture: In large-scale open-source hackathons, dozens of developers simultaneously edit shared registries, causing constant git merge conflicts. ArcadeVerse solves this by deriving the entire catalog dynamically from isolated game.json files.
  • Sandboxed Runtime Execution: When a user launches a game, it is mounted inside an isolated <iframe> sandbox. This prevents global variables, CSS styling, keyboard event listeners, and audio states from contaminating other games or the host shell.
  • Deterministic Algorithmic Evaluation: Contributor rankings, badges, and scores are computed transparently from verified repository files and live GitHub commits.
  • Accessibility by Default: Built-in WCAG 2.1 AA toggles (reduced motion, high contrast, text scaling, focus rings) ensure the arcade is inclusive to all players.
Pro-Tip for Contributors: Because the platform runs natively in any browser without a build step, you can develop and test your game simply by opening index.html directly or launching a local server with npx serve or VS Code Live Server.
02 / Game Architecture

Mandatory 4-File Game Specification

Every game submitted to ArcadeVerse must reside in its own dedicated directory following the exact convention: games/<game-name>_<your-github-username>/.

Within this directory, exactly 4 files are mandatory for pre-flight verification:

Required File Role & Entrypoint Mandatory Architectural Specification
index.html Standalone Game Entrypoint Self-contained canvas viewport. Only links local style.css and game.js. Responsive viewport meta tag mandatory.
style.css Scoped Game Stylesheet Zero external font/CSS CDNs. Scoped to the game canvas container, HUD overlays, and touch controls.
game.js Game Logic & Engine Loop Pure ES6+ JavaScript. Implements game loop and hooks into ArcadeVerse lifecycle bridge (pause, teardown).
game.json Metadata Descriptor Includes title, category, description, author, and github for automated catalog ingestion.
Directory Naming Rule: Use lowercase alphanumeric characters and hyphens for the game name, followed by an underscore _ and your exact GitHub username (e.g. quantum-minesweeper_babin).

02 / Game Architecture

Isolation & Sandbox Standards

To ensure zero cross-game interference, all community games must adhere to the following isolation rules:

  • Relative Linking Only: In your index.html, link assets using relative paths: <link rel="stylesheet" href="style.css"> and <script src="game.js"></script>. Never use absolute paths (e.g. /assets/ or /games/).
  • Self-Contained Storage Keys: If your game stores high scores or game states in LocalStorage, prefix keys with your game ID (e.g. localStorage.setItem('neon_runner_highscore', score)) to avoid overwriting other games' records.
  • Keyboard Listener Cleanup: Bind game controls within your canvas or document, and ensure the player can use standard arrow keys, WASD, or Spacebar.
  • Responsive Canvas Scaling: Set your canvas or UI to scale cleanly within its iframe container (width: 100%; height: 100%; max-width: 800px;).

Pre-Flight Game Validator CLI

The platform includes an automated pre-flight testing script: scripts/validate-games.js. Run it anytime via npm test.

Asset Integrity & Broken Link Checking

The validator statically inspects every game entrypoint (index.html, style.css, and game.js) to confirm all referenced local assets exist on disk before merge:

  • HTML Links & Scripts: Verifies <link href>, <script src>, <img src>, and <source src> paths.
  • CSS URL Attributes: Parses url(...) declarations in stylesheets, skipping data URIs and remote CDNs.
  • JS Media Instantiations: Scans for new Audio("path") and Image.src = "path" relative references.
Terminal (Asset Audit) 
# Run full validator with hub asset diagnostics:
node scripts/validate-games.js --audit-hub

# Strict asset resolution audit:
node scripts/validate-games.js --strict-assets --summary-json audit-report.json

Diagnostic Telemetry & Optimization Rules

The validator emits automated real-time optimization guidelines whenever audit checks complete. It alerts contributors regarding:

  • Asset Over-Budgeting: Flagging uncompressed sprites or sound effects exceeding 5MB to preserve snappy loading on mobile networks.
  • AudioContext Lifecycle Health: Recommending games instantiate sound nodes through ArcadeVerse.trackAudioContext() so sound halts on modal dismissal.
  • Doctype & Encoding Compliance: Checking for standard <!DOCTYPE html> declarations and explicit UTF-8 meta tags.
  • Isolation & Frame Breakout Prevention: Scanning inline attributes for references to parent or top window targets.
  • Static Script Security Heuristics: Flagging un-sanitized dynamic code executions (such as document.write or direct insertion of query parameters into innerHTML).

Automatic WebGL Context Disposal & Context-Loss Protection

To prevent GPU memory exhaustion when switching between complex 3D or 2D canvas games in modals, ArcadeVerse enforces strict WebGL resource management through assets/js/webgl-disposal.js and the SDK:

  • Proactive Hardware Teardown: closeGameModal() systematically inspects all iframe canvases and invokes WEBGL_lose_context.loseContext() before blanking src.
  • Context Restoration Protection: Games can register their contexts with ArcadeVerse.registerWebGLContext(gl, { onRestore }) to gracefully trap webglcontextlost without crashes.
  • Automated Buffer/Texture Tracking: Register GPU allocations via ArcadeVerse.trackTexture() and ArcadeVerse.trackProgram() for instant garbage collection upon modal dismissal.
  • Telemetry & Memory Footprint Monitoring: Track real-time context allocation stats via ArcadeVerseWebGL.getStats().

Implementation Guide for Game Contributors

When developing WebGL games for ArcadeVerse, always bind the context recovery handler. When a mobile or laptop GPU sleeps or switches display adapters, the browser triggers a synthetic context loss. With the ArcadeVerse lifecycle bridge, your game avoids black screens: 

// 1. Initialize Canvas & WebGL Context
const canvas = document.getElementById("gameCanvas");
const gl = canvas.getContext("webgl2") || canvas.getContext("webgl");

// 2. Register Context with ArcadeVerse SDK
if (window.ArcadeVerse && ArcadeVerse.registerWebGLContext) {
  ArcadeVerse.registerWebGLContext(gl, {
    onRestore: function (glInstance) {
      console.log("Restoring textures and rebuilding shader pipeline...");
      rebuildShaders(glInstance);
      rebuildGeometryBuffers(glInstance);
    }
  });
}

// 3. Register GPU allocations for automatic disposal
if (window.ArcadeVerse && ArcadeVerse.trackTexture) {
  ArcadeVerse.trackTexture(gl, playerSpriteTexture);
  ArcadeVerse.trackBuffer(gl, terrainVertexBuffer);
}

ArcadeVerse introduces a zero-dependency bi-directional postMessage communication protocol and client-side bridge implemented in assets/js/arcadeverse-sdk.js. This guarantees zero audio bleeding, prevents residual memory leaks, and cleanly manages iframe resources during modal transitions.

ARCADEVERSE_PAUSE

Dispatched by the shell whenever the modal loses focus or is requested to pause. Games immediately suspend timers, physics ticks, and background sound.

ARCADEVERSE_RESUME

Notifies the game iframe that modal presentation has resumed so audio contexts can wake and gameplay can continue smoothly.

ARCADEVERSE_TEARDOWN

Dispatched 100ms before modal unmounting. Cancels all active requestAnimationFrame loops, terminates Web Audio nodes, and clears intervals.

JAVASCRIPT 
// In your game.js or by importing assets/js/arcadeverse-sdk.js:
if (window.ArcadeVerse) {
  // 1. Two-way cryptographic session handshake authentication (#489)
  ArcadeVerse.onHandshake((sessionToken) => {
    console.log("[MyGame] Secure session established with ArcadeVerse hub:", sessionToken);
  });

  // 2. Automatically track Web Audio contexts for zero audio pop on close
  ArcadeVerse.trackAudioContext(myGameAudioContext);

  // 3. Track animation loop IDs
  const animId = requestAnimationFrame(gameLoop);
  ArcadeVerse.trackAnimationFrame(animId);

  // 4. Secure score dispatches authenticated with active session token
  ArcadeVerse.postScore(currentScore);

  // 5. Register custom teardown handler
  ArcadeVerse.onTeardown(() => {
    cancelAnimationFrame(animId);
    if (myGameAudioContext && myGameAudioContext.state !== 'closed') {
      myGameAudioContext.close();
    }
  });

  // 6. Listen for pause & resume events
  ArcadeVerse.onPause(() => { gameState = 'PAUSED'; });
  ArcadeVerse.onResume(() => { gameState = 'PLAYING'; });
}

Cryptographic Session Handshake Protocol (#489)

To prevent cross-site message spoofing, fake high-score submissions, and unauthorized modal termination, ArcadeVerse enforces a strict structured clone handshake on iframe communication:

  • Strict Origin Validation: All postMessage handlers reject transmissions whose event.origin does not strictly equal window.location.origin (with local file:// and null origin development tolerance).
  • Source Window Verification: Events are validated against event.source === gameIframe.contentWindow, guaranteeing that messages originate exclusively from the actively mounted game iframe.
  • Cryptographic Session Token: When the iframe loads, the parent hub dispatches an AV_INIT_SESSION challenge with a cryptographically secure token (crypto.randomUUID()). The child SDK confirms with an AV_SESSION_ACK and signs all subsequent runtime events (such as ARCADEVERSE_GAME_SCORE and keyboard shortcuts) with this token.

The ArcadeVerse catalog dynamically scans GAMES_REGISTRY upon initialization and continuously synchronizes category game counts across all active filter tabs.

JavaScript (Catalog Engine) 
// Dynamic category pill count synchronization
function updateCategoryPillCounts() {
  const counts = { all: GAMES_REGISTRY.length, favorites: getFavorites().size, halloween: 0 };
  GAMES_REGISTRY.forEach((g) => {
    const cat = (g.category || "").toLowerCase();
    counts[cat] = (counts[cat] || 0) + 1;
    if (g.tags?.includes("halloween") || cat.includes("horror")) {
      counts.halloween++;
    }
  });

  categoryPills.forEach((pill) => {
    const categoryKey = pill.getAttribute("data-category").toLowerCase();
    const badge = pill.querySelector(".pill-count-badge");
    if (badge) badge.textContent = counts[categoryKey] ?? 0;
  });
}

Fuzzy Suggestion Heuristics

The fuzzy recommendation pipeline evaluates query distance against platform vocabulary through a multi-tier matching strategy:

JavaScript (Levenshtein Distance Engine) 
function getSmartSuggestions(query, category) {
  if (!query) return ["All", "Arcade", "Puzzle", "Retro", "Action"];
  const q = query.toLowerCase().trim();
  const pool = new Set();
  GAMES_REGISTRY.forEach(g => {
    if (g.category) pool.add(g.category);
    g.tags?.forEach(t => pool.add(t));
  });
  const scored = [];
  pool.forEach(term => {
    const t = term.toLowerCase();
    let score = 0;
    if (t.startsWith(q)) score = 100 - (t.length - q.length);
    else if (t.includes(q)) score = 80 - (t.length - q.length);
    else {
      const dist = levenshteinDistance(q, t);
      if (dist <= 2) score = 60 - dist * 15;
    }
    if (score > 0) scored.push({ term, score });
  });
  return scored.sort((a, b) => b.score - a.score).slice(0, 4).map(s => s.term);
}
Interactive Chip Injection: Clicking any recommendation chip instantly updates the active filter category or updates the search bar, executing a silky-smooth catalog re-render with zero full-page reloads.
