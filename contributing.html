Contribution Guidelines

Everything you need to contribute to ArcadeVerse during NSOC Winter Edition 2026 — folder rules, point systems, PR workflow, and recognition tracks.

Strict Isolation Rules • Dual Point Systems • Conflict-Free Workflow
01

Welcome from the Project Admin

Welcome to ArcadeVerse! I am Debasmita Bose (@DebasmitaBose0), your Project Admin (PA) and Lead Architect for Nexus Spring Of Code – Winter Edition 2026.

ArcadeVerse is designed as an accessible, scalable, and conflict-free open-source gaming ecosystem. Whether you are writing your first HTML5 Canvas loop or crafting advanced game mechanics, you can build, collaborate, and showcase your work here.

I personally review every Pull Request, provide constructive feedback, and ensure your contributions are permanently celebrated on the live Hall of Fame Leaderboard.

03

Dual Point Systems

1. Official NSoC '26 Program Points

These are the official program points recorded on the central NSoC evaluation sheet. Labels are assigned exclusively by the Project Admin during review:

Label Points Scope
level1 3 pts Typo fixes, minor cosmetic changes, approved documentation
level2 5 pts Frontend UI enhancements, responsive styling, component layouts
level3 10 pts Verified playable games, complex physics, core architecture

2. In-App Arcade Points (Live Leaderboard)

These points power the real-time Hall of Fame rankings:

  • Verified Standalone Game: +100 pts base per playable game in games/
  • Mechanics & Physics Bonus: +25 pts for Canvas rendering, 60fps loops, sound FX, physics, or touch controls
  • Platform Feature PR: +50 pts per merged feature/UI PR
  • Quality & Bug Fix PR: +25 pts per merged bug fix or documentation enhancement
  • Merged Git Commits: +5 pts per verified commit
04

How to Get Your PR Merged

  1. Create or pick an issue → Comment and wait for assignment from the Project Admin. Do not start coding before assignment.
  2. 5-Day Target / 7-Day Auto-Unassign: Submit your PR within 5 days of assignment. After 7 days of inactivity the issue will be unassigned.
  3. Fork & Clone → Add the upstream remote.
  4. Create a separate branch (never work on main) — e.g. fix/issue-123 or feat/game-name.
  5. Code & Commit → Follow folder rules strictly, test thoroughly, write clear commit messages.
  6. Open the PR → Reference the issue with Closes #123 and provide a clear summary.
  7. Review & Merge → Address feedback promptly. The Project Admin will attach the official labels and merge.
05

Critical Rules (Must Follow)

1. Game Creation — Strictly 4 Files Only

Every game folder under games/<game-name_your-name>/ must contain exactly these 4 files:

  • index.html — Game canvas & markup (SVG / Lucide icons only — NO emojis)
  • style.css — Game styling
  • game.js — Game logic
  • game.json — Metadata for automated registry compilation

No README, no images, no audio, no subfolders, no extra files.

2. Folder Naming Convention (Mandatory)

Games must live in: games/game-name_your-name/
✅ games/cyber-pong_your-name/
❌ games/pong/ (ambiguous)
❌ Root directory or any other location

3. Never Edit games-registry.js

Game registration is 100% automated via GitHub Actions scanning your game.json. Manual edits to assets/js/games-registry.js are strictly prohibited and will cause merge conflicts.

4. Mandatory In-Game Instructions

Every game must include a clear “How to Play / Controls & Rules” screen or modal so the Project Admin can test and evaluate your mechanics during review.

06

How to Run the Project Locally

ArcadeVerse is 100% native web tech — no backend, no bundlers, no heavy dependencies.

  • Windows: start chrome "$PWD\index.html"
  • macOS: open index.html
  • Linux: xdg-open index.html
  • VS Code: Right-click index.html → “Open with Live Server”
  • Node (optional): npx -y live-server --port=5500
07

What is Not Allowed

  • Manually editing assets/js/games-registry.js
  • Adding README or documentation files inside game folders
  • Creating files or folders in the repository root
  • Creating games outside the games/ directory
  • Working directly on the main branch
  • Using frameworks (React, Vue, Angular, jQuery) or Python backends
  • Submitting AI-generated spam or unverified broken code
  • Opening PRs without an assigned issue
  • Using emojis instead of SVG / Lucide icons
  • Malicious code, tracking scripts, or cryptominers
08

Quick Checklist Before Opening a PR

  • Issue was officially assigned to me by the Project Admin
  • I am submitting within the 5-day target window
  • I worked on a separate branch (not main)
  • I have read the Code of Conduct
  • My change is meaningful, tested, and written in pure Vanilla HTML/CSS/JS
  • No files were created in the root directory
  • I did not modify games-registry.js
  • Game lives in games/game-name_your-name/ with exactly 4 files
  • Used SVG / Lucide icons only — no emojis
  • Added a clear in-game “How to Play” section
  • PR description includes Closes #issue-number
